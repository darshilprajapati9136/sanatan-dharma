# UI/UX Design Specification

# 1. Design Goal

The platform should feel like a modern, trustworthy, peaceful, and deeply respectful digital space for learning about Sanatan Dharma.

The design should avoid two extremes:

- Looking like a generic corporate education website
- Looking overly decorative, cluttered, or stereotypically religious

The desired visual balance is:

**Modern digital product + subtle Indian spiritual identity**

# 2. Core UX Principles

The website should follow these experience principles:

- Easy for beginners
- Fast to understand
- Calm and uncluttered
- Source transparency
- Mobile-first
- Clear content hierarchy
- Bilingual from the beginning
- Accessible
- Consistent
- Respectful of religious diversity
- Focused on learning, not distraction

# 3. Visual Personality

The visual identity should feel:

- Calm
- Sacred
- Warm
- Intelligent
- Trustworthy

---

- Premium
- Modern
- Indian
- Educational

The website should not feel loud, flashy, or entertainment-focused.

# 4. Design Direction

Recommended design theme:

## Modern Indian Spiritual

This means:

- Clean layouts
- Large readable typography
- Soft backgrounds
- Subtle traditional motifs
- Strong content cards
- Minimal animation
- Elegant Sanskrit presentation
- Warm visual tones
- High-quality illustrations or photography

Traditional design elements should be used sparingly.

# 5. Color Direction

A recommended starting palette:

## Primary

Deep saffron or muted orange

Used for:

- Main buttons
- Selected tabs
- Highlights
- Active navigation

---

## Secondary

Deep maroon or warm brown

Used for:

- Important titles
- Secondary accents
- Traditional visual elements

## Background

Warm cream or off-white

Used for:

- Main page backgrounds
- Reading areas
- Cards

## Dark Text

Charcoal or very dark brown

Used for:

- Body text
- Titles
- Navigation

## Accent

Muted gold

Used sparingly for:

- Premium details
- Scripture markers
- Decorative lines
- Verified badges

Avoid bright neon orange or excessive gold.

---

# 6. Dark Mode

Dark mode can be included later or in V1 if development allows.

Suggested dark mode feel:

- Deep charcoal background
- Warm cream text
- Muted saffron accents
- Minimal bright colors

Dark mode should remain readable and calm.

# 7. Typography

Typography should support:

- English
- Hindi
- Sanskrit
- Roman transliteration

Recommended typography structure:

## English

Modern serif or humanist sans-serif for titles.

Clean sans-serif for body text.

## Hindi/Sanskrit

Readable Devanagari font.

The Devanagari typography should feel elegant and not compressed.

## Scripture

Scripture text should receive special treatment.

Example:

- Larger font

---

- More line spacing
- Centered or well-contained layout
- Clear distinction from commentary

# 8. Typography Hierarchy

Recommended hierarchy:

H1 — Main page title

H2 — Major section

H3 — Subsection

Body Large — Introductory text

Body — Main reading text

Caption — Source, metadata, notes

Scripture — Dedicated style

Translation — Dedicated style

Commentary — Dedicated style

AI Output — Dedicated but neutral style

# 9. Layout Grid

Desktop:

- Maximum content width around 1200–1280 px
- Reading width around 700–800 px
- Wide cards where needed
- Generous whitespace

Tablet:

- Two-column layouts where suitable

---

Mobile:

- Single-column
- Large tap areas
- Sticky navigation where useful

# 51. Religious Symbols

Symbols such as Om should be used carefully.

Do not use sacred symbols as:

- Delete buttons
- Menu buttons
- Loading indicators
- Decorative clutter

Use them only where culturally appropriate.

# 52. Image Strategy

Use:

- High-quality original illustrations
- Licensed photography
- Carefully selected public-domain art
- Custom iconography

---

Avoid:

- AI images pretending to be historical artifacts
- Low-resolution deity images
- Watermarked images
- Random internet images

# 53. Illustration Style

Recommended:

Modern Indian editorial illustration.

Characteristics:

- Soft
- Elegant
- Respectful
- Detail without clutter
- Historically inspired where appropriate

# 54. Animation

Animations should be subtle.

Good:

- Fade
- Slide
- Soft hover
- Smooth page transition
- Card elevation

Avoid:

- Flashy particle effects
- Excessive spinning
- Constant movement
- Heavy religious animation

---

# 55. Loading States

Use simple skeleton loaders.

Example:

Scripture card loading.

AI answer loading.

Do not use sacred symbols as spinning loaders.

# 56. Error States

Example:

**We couldn't load this verse.**

Try again.

If a source is unavailable:

**This source is temporarily unavailable.**

Avoid vague error messages.

# 57. Empty States

My Library:

**You haven't saved anything yet.**

Explore Bhagavad Gita or save a concept to build your library.

Button:

**Explore**

---

# 58. Accessibility Requirements

Target WCAG 2.1 AA where possible.

Important:

- Keyboard navigation
- Screen reader labels
- Alt text
- Good contrast
- Visible focus states
- Large tap targets
- Text resizing
- Semantic HTML

# 59. Mobile-First Requirements

Mobile must not feel like a smaller desktop site.

Important mobile UX:

- One-column content
- Sticky bottom navigation
- Large buttons
- Verse text readable without zoom
- Expandable source sections
- Simplified filters
- Easy language switch

# 60. Desktop Experience

Desktop can provide:

- Side navigation on deep pages
- More related content
- Wider chapter navigation
- Split layouts
- Sidebar sources
- Better compare-commentary layouts

# 69. UX Success Criteria

The design should succeed if a first-time user can:

- Understand what the product does within seconds
- Find beginner learning easily
- Locate a scripture quickly
- Understand one Gita verse without confusion
- Ask an AI question
- See where the answer came from
- Switch language easily
- Save useful content
- Continue later

# 70. Key Differentiating UX

The website should visually separate:

**Scripture**

---

**Translation**

**Commentary**

**Modern Explanation**

**AI Explanation**

This separation should be obvious without requiring users to understand technical terms.

That transparency can become one of the strongest parts of the product.
